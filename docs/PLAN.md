# Agent Hub: plan

## The problem

Power users pay for several AI subscriptions (Claude Pro/Max, ChatGPT Plus/Pro for Codex, Gemini, GitHub Copilot) and often several accounts of the same one. Each has rolling usage limits (5-hour sessions, weekly caps, monthly premium requests). Today you switch by logging out and back in, lose track of which account has quota left, and let limits reset unused, which wastes money.

**Agent Hub** is a small desktop app (Windows, macOS, Linux) that:

1. Finds the AI accounts already on the machine.
2. Keeps each account in its own isolated config home, so all of them stay logged in at once.
3. Shows live usage limits, reset times and history for every account in one dashboard.
4. Launches the CLI (or desktop app where possible) with the account you pick, in one click, from the window or the tray.
5. Warns you before you hit a limit, tells you when one resets, flags quota that is about to reset unused, and recommends which account to use next.
6. Lets you choose, per account, what is shared with your main setup: skills, plugins, agents/commands, instructions, MCP config, settings, chat history.

## Tech choice

**Tauri 2**: Rust backend + React/TypeScript UI. A ~10 MB installer, low idle RAM (it lives in the tray all day), and native webviews on each OS (WebView2 / WKWebView / WebKitGTK). Rust handles credential files, process spawning and HTTP polling safely.

## How accounts are isolated

Every CLI supports pointing at an alternate home. Agent Hub creates one home per account and launches the CLI with the matching env var:

| Provider | CLI | Isolation | Credentials | Usage source |
|---|---|---|---|---|
| Claude | `claude` | `CLAUDE_CONFIG_DIR` | `<home>/.credentials.json` (Win/Linux), Keychain `Claude Code-credentials[-<hash>]` (macOS) | `GET api.anthropic.com/api/oauth/usage` (5-hour, weekly, weekly-Opus/Sonnet) + `projects/**/*.jsonl` |
| Codex (ChatGPT) | `codex` | `CODEX_HOME` | `<home>/auth.json` (force `cli_auth_credentials_store="file"`) | `GET chatgpt.com/backend-api/wham/usage` (primary/secondary windows) + `sessions/**/*.jsonl` rate_limits |
| Gemini | `gemini` | `GEMINI_CLI_HOME` or HOME override | `~/.gemini/oauth_creds.json` | `POST cloudcode-pa.googleapis.com/v1internal:retrieveUserQuota` |
| Copilot | `copilot` | `COPILOT_HOME` / XDG override | GitHub token | `GET api.github.com/copilot_internal/user` (premium requests) |

Sharing uses links: a junction on Windows (no admin needed), a symlink on macOS/Linux. Credential files are never linked or copied.

Desktop apps: Electron-based desktop apps (Claude Desktop) can run per-account with `--user-data-dir=<dir>`. Others are launched as-is and flagged as single-account in the UI.

## Architecture

```
src/                      React UI (Vite, Tailwind, Recharts, Zustand)
  shared/types.ts         Contract shared with Rust (mirrored in src-tauri/src/model.rs), incl. the command list
  shared/__fixtures__/    serde.ts, generated by `cargo test` from the Rust shapes and type-checked against types.ts
  api.ts                  Typed API over Tauri invoke; the mock backend when run in a plain browser
  store.ts                App state and actions (Zustand)
  screens/                Overview, Accounts, Knowledge, Skills, Notifications, Settings
  terminals/              Terminal grid: sessions, panes, xterm.js registry
  components/             Sidebar, Ctrl/Cmd+K launcher, add-account and export/import dialogs, shared UI
  lib/, charts/           Pure helpers (quota, grid, recommend, format...) and the usage charts
  mock/                   In-memory backend and demo data for `npm run dev`
src-tauri/src/
  lib.rs                  App setup, plugins, tray, background poller
  commands.rs             #[tauri::command]s, one per entry in the shared command list (thin wrappers)
  accounts.rs             Create, update, import and remove accounts; applying their sharing
  settings.rs             Merging a settings patch (from the UI or a setup file), saving and applying it
  model.rs                Rust mirror of src/shared/types.ts
  store.rs                JSON persistence in the app data dir (accounts, settings, notifications, history)
  sharing.rs              Junction/symlink management
  knowledge.rs            The shared profile per tool that accounts link skills, plugins and instructions from
  skills.rs               Search, preview and install skills from skills.sh into the shared profiles
  transfer.rs             Export/import of a setup (.agenthub), sign-ins encrypted with a passphrase
  launcher.rs             Open the user's terminal per OS with the account env
  pty.rs                  Embedded terminals for the grid (ConPTY / openpty via portable-pty)
  usage.rs                Poll loop, history, activity cache
  notify.rs               Rules: nearly exhausted, limit hit, reset, use-it-or-lose-it
  recommend.rs            Score accounts for "what should I use now"
  util.rs                 Small cross-platform helpers
  providers/{claude,codex,gemini,copilot}.rs, common.rs
site/                     Landing page, deployed to GitHub Pages
```

## Status

**Shipped (v0.2)**
- Detect installed CLIs and existing homes (including side-by-side homes like `~/.claude-h1`).
- Add, import, edit and remove accounts, with per-account sharing toggles and saved drafts of half-filled profiles.
- Launch the CLI in a new terminal, login flow, resume last session; desktop launch where supported. Per-tool permission modes.
- Live usage for Claude and Codex, best-effort for Gemini and Copilot; manual entry fallback.
- Dashboard: per-account limit bars, reset countdowns, usage-over-time and most-used charts.
- Notifications and recommendations. Tray menu with quick launch. Ctrl/Cmd+K launcher.
- Account-aware terminal grid inside the app (xterm.js + portable-pty): up to nine panes, each on its own account, in named sessions.
- Continue on another account: when a pane's account hits its limit, one click reopens the chat on the next account with resume and shared history. Resume reopens that exact conversation (the pane's own, else the account's newest in that folder), never one another live window still has open. Codex, Gemini and Copilot leave no live-process marker, so for them only the conversation a pane was started in is known while it runs (a pane started fresh resumes the account's newest in that folder), and only this app's own panes count as having one open.
- Shared knowledge: one shared profile per tool that every account links its skills, plugins, agents and instructions from.
- Skills explorer: browse and search skills.sh and install a skill into a tool's shared profile.
- Export/import of a setup between machines (`.agenthub` file, sign-ins optional and encrypted with a passphrase).
- Renamed to Agent Hub (the app identifier and data folders keep their earlier names, so existing data is kept).
- CI on Windows, macOS and Linux; tagged releases build installers with tauri-action. macOS bundles are signed ad hoc.
- Landing page on GitHub Pages: animated demo of the board, download buttons per OS with auto-detect, supported tools, privacy statement.

## Privacy and safety rules

- Everything is local. No telemetry, no server.
- Tokens are read only to call that provider's own usage endpoint, only when "live usage" is on (default on, can be turned off for local-logs-only mode). When Claude first refuses usage for an account, a call to its profile endpoint (same token) says why, e.g. a canceled subscription; it is repeated only while the reason is unknown.
- Never write to another tool's credential file except an atomic token refresh that keeps the file valid for the CLI. A login kept in the macOS Keychain is never written: when it expires, the CLI renews it itself (Claude: `claude mcp list`, which makes no model request), so the CLI's own renewal lock is respected.
- Uninstall leaves every CLI home intact.
- Export follows links to skills kept elsewhere, but never into an account or tool folder, so a setup file carries sign-ins only when the user includes them (encrypted).
- An offline or refused request never reads as signed out: each provider types its errors (auth, expired, network, blocked, other). A blocked account (signed in, but its plan has no CLI access) drops its old numbers, is never recommended or launched, and stays blocked through temporary failures until a check succeeds or it is signed out. An expired login is one that renews by itself; one only the user can fix is a sign-in problem.
